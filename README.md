## `01 / THE IDEA`

### Engineering shouldn't be locked behind expensive tools.

Robotics is a fascinating intersection of software, electronics, mechanics, and mathematics. But getting started often means navigating disconnected tools, complicated workflows, and expensive hardware.

**MagicSmoke is our attempt to bring these worlds together.**

We are building an open-source ecosystem where ideas can move from code and circuits to interactive simulations and, eventually, physical machines.

The goal is simple:

> Make experimenting with engineering easier, more visual, and more accessible to everyone.

## `03 / OUR VISION`

### One connected engineering workflow.

```text
       ┌──────────────────────┐
       │        DESIGN        │
       │   Circuits & Models  │
       └──────────┬───────────┘
                  │
                  ▼
       ┌──────────────────────┐
       │         CODE         │
       │  Logic & Controllers │
       └──────────┬───────────┘
                  │
                  ▼
       ┌──────────────────────┐
       │       SIMULATE       │
       │   Test & Experiment  │
       └──────────┬───────────┘
                  │
                  ▼
       ┌──────────────────────┐
       │         BUILD        │
       │   Real-world Robots  │
       └──────────────────────┘
```

We want to reduce the friction between having an idea and testing it.

Our long-term direction is to explore a connected workflow where developers can design a system, write its control logic, observe its behavior in simulation, and bring it into the physical world.

We are building toward this vision incrementally, starting with practical tools and real experiments.

## `04 / OUR PRINCIPLES`

**01 — Open by default**

We believe useful engineering tools should be accessible, understandable, and open to community contributions.

**02 — Learn by building**

The best way to understand a system is to experiment with it. We value interactive tools and working prototypes over abstract explanations alone.

**03 — Respect the engineering**

Good interfaces matter, but they must serve reliable functionality. We aim to build tools that are both enjoyable to use and technically useful.

**04 — Experiment without fear**

Prototypes, failed experiments, and unconventional ideas are part of the process. Progress comes from testing assumptions and learning from results.
